# 4.2 BEM + Clay CSS Coexistence in DXP

## File Structure

```text
src/css/
  _tokens.scss
  _theme-airline.scss
  _airlines.scss
  _typography.scss
  _scope.scss
  _reset-clay.scss
  _components.scss
  _hero.scss
  main.scss
src/WEB-INF/liferay-look-and-feel.xml
```

## Scope and Naming

Put `data-dxp-scope` only on custom theme-owned layout regions. All custom classes use the `dxp-` BEM namespace, for example `dxp-card`, `dxp-card__header`, and `dxp-card__header--active`. The `scope()` mixin emits `[data-dxp-scope] .dxp-*`, increasing specificity over a single Clay utility class without `!important` and without affecting unrelated portlets.

```html
<section data-dxp-scope class="dxp-layout">
  <div class="dxp-layout__portlet">
    <div class="portlet-boundary">...</div>
  </div>
</section>
```

`_reset-clay.scss` intentionally resets only direct portlet drop-ins owned by `.dxp-layout__portlet`. It also offers `.dxp-layout__legacy-grid` for a controlled legacy Bootstrap `.container`/`.row` region. Do not apply that class to an entire page or a generic portlet container, because it would remove Grid spacing from third-party content.

The hero is RTL-aware through logical properties (`padding-inline`, `text-align: start`, and `justify-self: start`). These automatically flip for `<html dir="rtl">`; it needs no fragile left/right override. Supply its image through `--dxp-hero-image` on the hero element, ideally from an escaped, whitelisted theme or content configuration value.

## Load Order

`liferay-look-and-feel.xml` defines theme metadata and settings; it does not control Sass import order. Keep the generated Clay imports first in `main.scss`, then import the local partials in this order:

```scss
@use "clay/atlas";
@use "clay/base";

@use "tokens";
@use "airlines";
@use "typography";
@use "scope";
@use "reset-clay";
@use "components";
@use "hero";
```

The checked-in sample `main.scss` assumes Clay is already loaded by the parent theme. In a standalone theme, retain the generator-provided Clay entries above the custom imports. The included `liferay-look-and-feel.xml` demonstrates the `airline-code` setting consumed by `portal_normal.ftl`.
